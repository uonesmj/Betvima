# Betvima continuous delivery

- `https://preview.betvima.com/`: authenticated compiled preview, automatically built after a debounced local edit or a main/codex branch push. Failed builds retain the previous compiled preview.
- `https://preview.betvima.com/dev`: authenticated development preview with Next.js hot reload. The per-user Windows login task `BetvimaPreviewWatch` sends source deltas using a key restricted to preview synchronization. The computer must be awake and logged in for uncommitted edits to sync. GitHub pushes continue independently.
- Preview intentionally has no production database, Supabase credentials, payment/notification/provider keys or financial workers. Account/payment flows and real sports feeds are unavailable until an isolated test dataset is configured. Network namespaces prevent preview code from reaching production, even on the same host; browser connections are restricted to its own origin. Nginx blocks financial routes and mutation requests.
- Preview builds use a separate user and network namespace, CPU quota, memory limit and low scheduling priority. Production builds use another user so preview cannot inspect their environment. New dependency sets are fetched by the OS npm with lifecycle scripts disabled, no app credentials, and HTTPS npm-registry-only lockfile URLs. Preview/test/build execution remains offline. Non-registry or linked dependencies stop publication for review. CRLF/LF changes alone are accepted.
- GitHub Actions checks units, TypeScript, lint, build and controller regressions. It then sends a short-lived GitHub-signed OIDC token over TLS. No server SSH private key or production credential is stored in GitHub. Server policy pins repository/owner IDs, workflow path, revision, audience and event; consumed tokens cannot be replayed.
- Production requires the owner to run the workflow on main with `approve_production=true`, or explicitly authorize Codex to dispatch that exact workflow/revision. Merely pushing code or passing tests never grants production approval. A branch that moves before deployment is rejected. No integration/financial test runs against production.
- The installed root controller rechecks tests and builds with production settings in a private network namespace, verifies the database backup and migration compatibility, starts one new web process, backs up web routing, and switches traffic only after candidate health checks. Failed public checks restore the previous web route. Existing financial workers are not changed. A migration file change stops deployment; migrations are never automatically applied.
- Keep old web processes/release assets during the rollback window. Database restore is never part of an automatic web rollback. Full archive validation does not replace an isolated restore rehearsal.
- Root tools are installed from reviewed copies under `/usr/local/lib/betvima-continuous`; deploying a commit cannot update those privileged tools. Changes to this directory's controller/installer code require an administrator-reviewed installation. Raw failure logs stay root-private under `/var/lib/betvima-continuous`.
- Preview login is stored only in a protected local artifact file. Existing root emergency and audit access remain intact.
