# Internationalisation, RTL, responsive layout, PWA and SEO

## Languages

* **fa-IR is the default** (`NEXT_PUBLIC_DEFAULT_LOCALE=fa`, `NEXT_PUBLIC_DEFAULT_DIR=rtl`); English is
  a first-class second locale. The layout sets `dir` and `lang` on `<html>` from configuration, and
  the whole design is **RTL-first**: Tailwind logical properties (`ms-`, `me-`, `ps-`, `pe-`,
  `start-`, `end-`, `inset-inline`) are used everywhere, so the same components mirror correctly for
  English without a second stylesheet.
* Dictionaries live in `src/lib/i18n/` and are accessed with `useT()`; missing keys fall back to the
  key itself, which is visible in review rather than silently rendering an empty string.
* Numbers, dates and money are formatted with `Intl` (`formatMinor`, `formatDateTime`,
  `formatInZone`) — no locale logic is hand-rolled, and no formatted value is ever parsed back into
  a calculation.
* **Timezone policy**: settlement windows default to `Asia/Tehran`, display timezone is configurable
  (`NEXT_PUBLIC_DISPLAY_TIMEZONE`), and all window maths goes through `src/lib/timezone/index.ts`
  (`Intl`-based, DST-correct, unit-tested against Berlin summer/winter and spring-forward gaps).

## Responsive contract

Tested at **360, 375, 390, 414, 768, 1024, 1280, 1440 and 1920 px** with zero horizontal overflow
asserted on `/`, `/live`, `/sports/football`, `/match/[id]`, `/bets`, `/wallet`,
`/account/profile`, `/affiliate/dashboard`, `/admin/dashboard` and `/help` — including with the bet
slip open. `nova-container`, `nova-tab`, `nova-table` and the `xs` breakpoint (360 px) are the shared
layout primitives; the desktop bet-slip rail and the mobile bottom sheet are the same component tree
so behaviour cannot diverge between breakpoints.

## PWA

* The manifest is generated by `src/app/manifest.ts` (served at `/manifest.webmanifest`): standalone
  display, theme/background colours, maskable icon, `lang`/`dir` from configuration, start URL `/`.
* `public/sw.js` caches the **app shell only** and explicitly never caches `/api/` responses; odds,
  balances and bets always come from the network.
* `/offline` gives a usable offline page instead of a browser error.
* Installability plus a `PwaRegister` component that degrades silently on unsupported browsers.

## SEO

* Per-page metadata (title/description/OG/Twitter), canonical URLs derived from
  `NEXT_PUBLIC_SITE_URL` (never hard-coded), `sitemap.xml` and `robots.txt` generated from the route
  map — `robots.txt` disallows `/admin`, `/api`, `/account`, `/wallet` and `/affiliate`.
* `lang`/`dir` attributes, semantic headings and `aria-label`s on interactive controls.
* Live/match pages are `force-dynamic` (odds change constantly); nothing financial is indexable or
  cacheable.
